# 또 다른 나, 아이(AI)

Pleos Connect를 목표로 만든 **독립 실행형 시연 Android 앱**입니다. 약속과 도착 예상의 변화를 연결하고, 통화·길 안내가 끝난 뒤 필요한 행동을 제안합니다. Kotlin · Jetpack Compose · minSdk 29 · DataStore를 사용합니다. 네트워크 없이 실행되며 외부 AI 서비스나 계정은 필요하지 않습니다.

## 실행

JDK 17과 Android SDK 35 / Build Tools 35가 필요합니다. Gradle 8.13 wrapper가 포함되어 있습니다. 최초 빌드는 의존성을 내려받으므로 인터넷이 필요합니다.

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
export JAVA_HOME="$HOME/Library/Java/JavaVirtualMachines/corretto-17.0.7/Contents/Home"
./gradlew testDebugUnitTest assembleDebug
sh scripts/build-demo.sh
```

두 번째 명령은 같은 검사 후 APK와 SHA-256 값을 `dist/`에 복사합니다.

```sh
"$ANDROID_HOME/platform-tools/adb" install -r dist/another-me-demo-debug.apk
"$ANDROID_HOME/platform-tools/adb" shell am start -n app.anotherme.demo/.MainActivity
```

일반 태블릿 또는 Android Automotive OS 에뮬레이터에서 설치합니다. 여러 기기가 연결되면 adb에 `-s 기기ID`를 추가합니다. 가로 1920×720 기준이며, 다른 가로 화면에서는 비율을 유지해 맞춥니다. 비율이 다르면 검정 여백이 생깁니다. 화면이 매우 좁은 분할 창에서는 버튼이 작아질 수 있어 실제 차종별 검증이 필요합니다.

debug 서명 키는 최초 빌드 때 `.local/debug.keystore`에 자동 생성됩니다. 저장소에는 포함하지 않습니다. 다른 개발 환경에서 새 키로 빌드한 APK가 기존 설치와 충돌하면 기존 앱 삭제 후 설치해야 하며, 삭제하면 로컬 입력도 지워집니다. 배포용 서명은 설정하지 않았습니다.

## 시연 순서

1. 처음에는 **최소화** 상태입니다. 왼쪽 세로 띠만 표시하고 나머지는 검정으로 비웁니다. 위쪽에는 `맡긴 일 / 먼저 챙김 / 펼치기`, 아래쪽에는 **AI 다이얼**이 있습니다.
2. `펼치기` → **중간(왼쪽 절반 1:1)** → `전체 화면` → **확장** → `접기`로 전환합니다. 이는 앱 안의 표시 영역 전환입니다.
3. `14:48 상황 재생`을 누릅니다. 약 8초 동안 **도착 예상 14:55 → 15:08 / 통화 중 → 길 안내 중 → 제안** 순서로 진행됩니다. 통화·안내 중에는 제안 확인 버튼이 나타나지 않습니다. 종료 시 여전히 필요한 한 건을 제안하고, 최소화 상태라면 중간으로 펼칩니다.
4. “8분 늦을 예정이에요. 대현님께 도착 예정 시간을 문자로 보낼까요?”와 **받는 사람·보낼 내용**을 확인합니다. `보내 줘`와 `괜찮아`는 AI 다이얼과 분리된 확인 버튼입니다. **시연: 실제 발송 안 됨**이 표시됩니다. 동의해도 문자를 보내지 않았다고 명시합니다.
5. `초기화`하면 시연 상태와 일시적인 전달 이력을 지웁니다. 저장한 맡긴 일은 유지합니다. `먼저 챙김 · 끔`에서는 자동 제안하지 않고, 통화·안내가 끝난 뒤 AI 다이얼을 눌러 직접 확인할 수 있습니다.
6. 확장 화면에서 `+ 맡긴 일 추가` → 날짜·시간·목적지·연락 상대·부탁 입력 → `내용 확인` → `확인하고 저장`합니다. 목록에서 수정·삭제할 수 있습니다. `P · 주차`를 누르면 가짜 주행 상태로 바뀌며 추가·수정·삭제가 잠깁니다. 재생 중에도 입력이 잠깁니다.
7. 확장 화면 하단에서 `스타일 A · 새틴 바 / 스타일 B · 다크 키`를 바꿉니다. **차종에 따라 버튼 스타일은 다를 수 있습니다.** 두 스타일은 일반화한 시연 표현이며 특정 제조사 인증 부품이 아닙니다.

시연 약속(15:00, 예시 상대)은 저장된 맡긴 일과 분리된 임시 데이터입니다. 첫 실행의 빈 목록에는 직접 입력한 일만 저장됩니다. 사용자가 등록한 목적지는 실제 내비 경로에 연결되지 않아 **경로 연결 필요**로 표시됩니다. 임의의 이름을 실제 연락처로 간주하지 않습니다.

## 코드와 디자인 수정

- `app/src/main/java/app/anotherme/demo/ui/DemoTheme.kt`: 화면 기준 크기·색·글자 크기·간격·키·다이얼·확인 버튼 값. v9 왼쪽 띠에 요청된 v10 방향(큰 키·아래 AI 다이얼·별도 확인 버튼)을 반영했습니다. 최종 v10 시안 일치 검증은 별도입니다.
- `ui/DemoApp.kt`: 세 모드, 두 키 스타일, 확인 화면과 입력 화면.
- `domain/DecisionEngine.kt`: Android에 의존하지 않는 판단 엔진. 출력은 `SPEAK_NOW / WAIT / DISCARD`입니다.
- `source/Sources.kt`: `VehicleSource / NaviSource / CallSource`와 가짜 입력. 실제 SDK 연결 지점은 TODO 주석에 있습니다.
- `data/TaskRepository.kt`: DataStore 로컬 저장·수정·삭제. 기기 백업은 비활성화했습니다.

판단 엔진은 통화·안내·불명확한 신호를 기다리고, 대기 후보를 최신 한 건으로 교체합니다. 약속보다 늦지 않거나 취소·경로 불일치·만료이면 폐기합니다. 질문을 했다는 사실과 답변이 전달됐다는 사실을 구분하며, 답변을 실제 표시한 뒤 `recordAnswer`로 같은 일정·약속 시각·ETA 조합의 반복을 막습니다. 새로운 ETA는 새 도움 후보로 평가합니다. ETA가 이전 값으로 되돌아오더라도 이미 전달한 조합은 반복하지 않습니다. 전달 이력은 시연 세션 메모리에만 있고 앱 프로세스 종료·초기화 시 사라집니다.

## 검사

```sh
./gradlew testDebugUnitTest assembleDebug
# 기기/에뮬레이터가 연결되어 있을 때 UI·저장 검사
./gradlew connectedDebugAndroidTest
```

단위 테스트 25개: 정시·조기 도착, 통화·안내 차단, 최신 한 건, 이미 답한 질문, 중복, 취소·경로 변경·만료, 신호 누락, 먼저 챙김 끔, 자정 통과, 전체 재생 흐름 등을 검사합니다. 실행 증거는 `docs/verification.md`에 기록합니다.

## 실제 연동이 안 된 부분

- **Pleos Vehicle/NaviHelper SDK를 포함하거나 호출하지 않습니다.** 차량 주행/주차, 통화 상태, 안내 중 여부, 목적지·ETA는 모두 가짜 입력입니다. 휴대폰 일정·연락처·실제 위치·내비·문자는 연결되지 않습니다.
- 실제 문자 발송 권한·네트워크·마이크·통화 접근 권한을 요청하지 않습니다. `SPEAK_NOW`는 화면 제안을 표시할 시점이며 **TTS 음성 출력·STT·Gleo·LLM은 구현하지 않았습니다.**
- 실제 차에서는 `CarUxRestrictionsManager`와 신호 신선도·연결 해제·권한을 검증해야 합니다. 가짜 `P/D` 버튼은 차량 주행 제한을 대신하지 않습니다. `distractionOptimized`를 선언하지 않아 실제 차량에서는 주행 중 실행이 제한될 수 있습니다. 실차 주행용 앱·심사 통과 결과물이 아닙니다.
- 검정 영역에 다른 앱을 실제로 띄우지 않습니다. 다른 앱 위 오버레이, Pleos 시스템 분할 창 크기 변경, 시스템 전체 화면 API, 자동 부팅·백그라운드 알림을 구현하지 않았습니다.
- 맡긴 일에는 목적지·연락 상대를 문자열로 저장합니다. 실제 경로 일치·수신자 검증·번호 선택은 후속입니다. 사용자가 입력한 일을 실제 차량 조건에 따라 실행하는 기능도 후속입니다.
- 원본 기획·디자인 저장소를 수정하지 않았습니다. 원격 연결·push·제출·게시를 수행하지 않았습니다.
